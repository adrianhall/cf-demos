# URL Shortener

An independently deployable Cloudflare Workers and Workers KV demo. Administrators create short links in a Vue application, while public `/l/<code>` requests redirect at the edge and produce structured Workers Logs events.

## Architecture

```text
Administrator -> Cloudflare Access -> /admin and /api/links -> Worker -> Workers KV
Visitor ----------------------------------------------------> /l/:code -> Worker -> 302 destination
                                                                  |
                                                                  +-> Workers Logs: short_link_used
```

Terraform owns the Worker service, KV namespace, custom domain, Access policies/applications, and observability settings. Wrangler owns Worker code versions and static assets.

This demo uses two Wrangler configuration files:

- `wrangler.local.jsonc`: committed, static, and used by every local command (`dev`, `build`, `test:integration`, `types`). It never depends on Terraform and always works from a clean checkout.
- `wrangler.jsonc`: generated by `npm run deploy` from `wrangler.jsonc.tpl` and live Terraform outputs. It is gitignored and only exists after a deployment run.

The public Access application bypasses the hostname. The more-specific `/admin*` and `/api/links*` Access application requires the configured `ADMIN_EMAIL`; `/` performs a document-level redirect to `/admin` before Vue mounts so the UI is never rendered anonymously. The Worker does not check the Access application audience (`aud`) claim — it accepts any valid Cloudflare Access JWT for `CLOUDFLARE_TEAM_DOMAIN`, not only one minted for this specific Access application. This is a deliberate simplification for a demo with no real administrator data; see `src/worker/middleware/access.ts` for the tradeoff. Local development always uses the toolkit's dev-token bypass instead of a real Access JWT.

## Prerequisites

- Node.js 24 or newer and npm 11 or newer.
- Terraform 1.10 or newer.
- A Cloudflare zone for `cfapps.uk` with no conflicting `link.cfapps.uk` CNAME.
- A Cloudflare Access team and an identity provider that can authenticate `ADMIN_EMAIL`.
- An API token scoped to the target account and zone with:
  - Account: Workers Scripts - Edit
  - Account: Access: Apps and Policies - Edit
  - Account: Workers KV Storage - Edit

Use a remote, encrypted Terraform state backend for shared or production operation. The local state files are ignored and must not be committed.

## Configuration

Create the operator environment file:

```sh
cd demos/url-shortener
cp .env.example .env
```

Set every value in `.env`:

- `CLOUDFLARE_API_TOKEN`: API token with the required permissions.
- `CLOUDFLARE_ACCOUNT_ID`: account that owns the Worker, KV namespace, and Access applications.
- `CLOUDFLARE_ZONE_ID`: zone ID for `cfapps.uk`.
- `DEMO_DOMAIN`: `cfapps.uk`.
- `DEMO_NAME`: `link`, producing `link.cfapps.uk`.
- `ADMIN_EMAIL`: only user allowed to access the management UI and API.
- `CLOUDFLARE_TEAM_DOMAIN`: Access team domain without `https://`, such as `example.cloudflareaccess.com`.

Do not commit `.env`, Terraform state, the generated `wrangler.jsonc`, or generated binding types (`worker-configuration.d.ts`).

## Local Development

Install dependencies and start the local Worker/Vite server:

```sh
npm install
npm start
```

`npm start` serves the Worker and admin UI against the local Wrangler configuration, which points `LINKS` at a simulated local KV namespace. The Vite Access plugin presents a local Access login flow before `/` or `/admin`, returns `401` rather than login HTML for unauthenticated management API requests, and leaves `/l/*` public. It is development-only. The Worker enables development tokens only through `import.meta.env.DEV`.

Open `http://localhost:5173/admin`. Local data resides in `.wrangler/` and can be removed between sessions.

## API

All management endpoints require Cloudflare Access in production.

| Method | Path | Behavior |
| --- | --- | --- |
| `GET` | `/api/links` | List links, newest update first. |
| `POST` | `/api/links` | Create from `{ "destination": "https://..." }`. |
| `PUT` | `/api/links/:code` | Replace destination while preserving the code. |
| `DELETE` | `/api/links/:code` | Delete a link. |
| `GET` | `/l/:code` | Public `302` redirect with `Cache-Control: no-store`. |

Unsafe schemes, invalid JSON, oversized bodies, and unknown codes return RFC 9457 `application/problem+json` errors.

## KV Consistency

Workers KV is eventually consistent globally. A write is visible immediately in its local network location but can take up to about 60 seconds to propagate elsewhere. The demo UI updates its local state from the create/update response; during a live presentation, use the short URL from the same location after creation. The immutable generated codes use cryptographically secure random bytes, so collision risk is negligible and does not depend on a globally consistent read-before-write check.

## Testing And Validation

```sh
npm run check
npm run test
npm run test:coverage
npm run build
terraform -chdir=infra fmt -check
terraform -chdir=infra init
terraform -chdir=infra validate
```

`test:unit` runs the Worker and client unit projects. `test:client` covers Vue components, browser bootstrap, and Pinia API state in jsdom. `test:integration` runs in workerd with the configured KV binding and verifies Access enforcement, authenticated CRUD, redirect headers, missing-link errors, and the informational usage log. The combined suite enforces complete source coverage through `npm run test:coverage`.

## Deployment

Deploy the complete demo:

```sh
cd demos/url-shortener
npm run deploy
```

`npm run deploy` chains, via [npm-run-all2](https://github.com/JoshuaKGoldberg/npm-run-all2)'s `run-s`, the following atomic steps (each independently runnable):

| Step | Script | Behavior |
| --- | --- | --- |
| 1 | `deploy:infra:init` | `terraform init` in `infra/`. |
| 2 | `deploy:infra:apply` | `terraform apply -auto-approve`; reads all configuration from `.env` via the Terraform `dotenv` provider. |
| 3 | `generate:wrangler` (via the `predeploy:worker` hook) | Writes `wrangler.jsonc` from `wrangler.jsonc.tpl` and the new Terraform outputs. |
| 4 | `generate:types` (via the `predeploy:worker` hook) | Regenerates `worker-configuration.d.ts` from the generated `wrangler.jsonc`. |
| 5 | `deploy:worker` | Builds the frontend and Worker bundle against `wrangler.jsonc` (`vite build`), then runs `wrangler deploy`, which follows the Vite-generated redirect config (`.wrangler/deploy/config.json`) to deploy that exact bundle. |

It does not create or expose any secret bindings.

Verify deployment:

1. Visit `https://link.cfapps.uk/admin` and authenticate as `ADMIN_EMAIL`.
2. Create a link to an HTTPS customer URL.
3. Open the generated `/l/<code>` URL in a new tab and confirm the destination loads.
4. In **Workers & Pages** > **url-shortener** > **Logs**, filter for `short_link_used`.

## Observability

Terraform enables persisted Workers Logs at 100% sampling and traces at 10% sampling. The Worker emits a structured informational event shaped like:

```json
{
  "level": "info",
  "message": "short_link_used",
  "code": "generated-code",
  "requestId": "cf-ray-or-generated-id",
  "service": "url-shortener"
}
```

The event deliberately excludes access tokens, authorization headers, visitor IP addresses, and full destination URLs. `LOG_LEVEL` in `wrangler.jsonc.tpl` (and `wrangler.local.jsonc` for local development) controls Worker log verbosity; use `info` for the presentation path.

## Troubleshooting

| Symptom | Cause and resolution |
| --- | --- |
| Access denies `/admin` | Confirm `ADMIN_EMAIL`, team domain, and configured identity provider. Re-run `npm run deploy` after correcting `.env`. |
| `401` from `/api/links` in production | Confirm `CLOUDFLARE_TEAM_DOMAIN` in `.env` matches the real Access team domain; a mismatch fails JWKS verification even for an otherwise-valid Access JWT. The Worker deliberately does not check the Access application audience (see the Architecture section), so a missing audience is never the cause. |
| Short URL briefly returns 404 or an old destination | Wait for Workers KV propagation, then retry. Do not configure a long KV `cacheTtl` for mutable links. |
| Domain fails to provision | Remove the conflicting DNS record and confirm the supplied zone ID owns `cfapps.uk`. |
| `infra:generate-wrangler` fails | Run `npm run infra:apply` successfully first; required Terraform output values must exist. |
| Logs are missing | Confirm the deployed Worker is the Terraform-created service and filter Workers Logs for `short_link_used`. |

## Teardown

Destroy all named demo resources:

```sh
cd demos/url-shortener
npm run teardown
```

The command removes the Access applications and policies, custom domain, KV namespace, and Worker service through Terraform. Confirm no `link` Worker, KV namespace, or Access applications remain in the account before discarding local Terraform state.
